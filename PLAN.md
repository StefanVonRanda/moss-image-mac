# MOSS capabilities into the app

Two repos. **App**: this repo (`~/moss-mlx/app`, Swift, `./build.sh`, `./tests.sh`). **Engine**: `~/moss-mlx/src`
(moss-image-mlx; remotes `origin` = felix-ab upstream, `fork` = StefanVonRanda), run by the app as
`~/moss-mlx/bin/moss-mlx`, venv python `~/moss-mlx/bin/python`, tests `cd ~/moss-mlx/src && ../bin/python -m pytest -q tests`.
Engine changes ship as `git format-patch` files in `app/patches/` that `setup.sh` applies to a pinned upstream
commit (`PIN=` in `setup.sh`). Every engine phase: commit in `~/moss-mlx/src`, regenerate `app/patches/` from the
whole series, prove the series applies with `git am` to `PIN` in a scratch clone and yields the same tree as
`~/moss-mlx/src`, then commit the app repo.

Machine: 24 GB Mac, compact tier cached (`--model compact`), LoRAs in `~/moss-mlx/loras` (8-step DMD:
`MOSS-Image-SFT-8-steps-dmd.safetensors`), mode adapters in `~/moss-mlx/adapters/`. One render at a time (memory).
A real render = run the CLI, look at the PNG (Read it), report seconds and `mlx_peak_memory_gb`. Test image:
`~/Pictures/MOSS Image/moss-2026-10-22T12-59-59Z-581600-820.png`. Never launch the app GUI (the user tiles
windows); check UI with offscreen renders (NSHostingView + cacheDisplay, see git log for "offscreen").
Commit messages: what was missing, how it was checked, what was not checked (house rules).
